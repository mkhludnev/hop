= Solr output

The Solr output transform indexes one JSON document from each incoming row using SolrJ.
It sends each document synchronously and passes the original row on only after Solr accepts the update.
An invalid document or failed update fails the transform.

== Options

[options="header"]
|===
|Option|Description
|Solr collection or core URL
|HTTP(S) URL including the core or collection name, for example `http://localhost:8983/solr/products`.
|JSON document field
|Input field containing a JSON object for each row.
|Commit within (milliseconds)
|Optional positive integer. If empty, Solr's configured commit policy applies.
An accepted update is not necessarily immediately visible to searches.
|===

The URL and commit-within option support Hop variables. This transform does not configure authentication.
Use a URL reachable from each Hop worker and configure the Solr server's authentication and TLS appropriately.

== Nested documents

JSON objects become named child documents and arrays of objects become lists of named child documents.
Arrays of scalar values become multivalued fields. `_childDocuments_` is also supported for unnamed child documents.
Mixed object/scalar arrays and nested arrays are rejected. The root must be a single JSON object.
Integers must fit in a signed 64-bit value; floating-point numbers are represented as double precision.

[source,json]
----
{
  "id": "product-1",
  "name": "Jacket",
  "tags": ["outerwear", "winter"],
  "skus": [
    {"id": "sku-1", "color": "blue", "manual": {"id": "manual-1", "title": "Care"}}
  ]
}
----

Configure Solr's schema for nested documents, including `_root_` and, for named paths, `_nest_path_`.
All document IDs must satisfy the collection's unique-key requirements.
See the https://solr.apache.org/guide/solr/latest/indexing-guide/indexing-nested-documents.html[Solr nested documents guide].
